# 대화 응답 시간 예산 v3 검증 요청

- **요청자**: AI 파트
- **작성일**: 2026-08-16
- **우선순위**: 필수
- **대상**: 프론트엔드 파트

> **대체됨**: [v2](message-response-time-budget-v2.md)의 18초 가정은 적용하지 않는다.

## 배경

팀 결정으로 대화 AI는 최초 포함 최대 10회, 각 시도 최대 10초를 쓴다. `/analyze`와
`/respond`가 모두 필요한 한 발화는 최악 약 204초가 걸릴 수 있다. 백엔드는 105초씩
기다리고 AI Worker가 재시도를 단독 처리한다.

## 요구사항

1. `POST /api/sessions/{sessionId}/messages`를 15초 등 임의의 짧은 타이머로 취소하는
   `AbortController`·클라이언트 타임아웃이 없는지 확인한다.
2. 자체 취소값이 있다면 제거하거나 최소 215초 이상으로 맞춘다. 프론트가 같은 발화를 다시
   보내는 재시도 로직은 추가하지 않는다.
3. 대기 중에는 기존의 생각 중 UI를 유지한다. 최종 실패 시 백엔드가 돌려준 안전 폴백을
   일반 캐릭터 응답으로 렌더링하고, 기술 오류 팝업으로 아이를 막지 않는다.
4. 네트워크 오류 뒤 사용자가 누르는 ‘다시 시도하기’는 기존 실패 요청을 한 번만 재전송한다.
   자동 재시도·발화 중복 전송은 만들지 않는다.
5. 브라우저 로그·분석 도구에 아이 원문 발화를 새로 남기지 않는다.

## 완료 조건

- [x] 정상 응답과 15초 초과 대기 케이스에서 요청이 클라이언트에서 먼저 취소되지 않는다.
- [x] 실패 폴백이 에러 화면 대신 대화 흐름으로 보인다.
- [x] 기존 STT/TTS·미션·단어장 요청이 영향을 받지 않는다.

### 프론트 반영 (2026-08-16)

`frontend/src/lib/api/speech.ts`의 `RESPOND_TIMEOUT_MS`를 10초 → **215초**로
올렸습니다(`PlayScreen.tsx`의 `submitUtterance` 호출에만 적용 — `completeScene`·
`getSession`은 AI 응답과 무관해 기존 15초(`API_TIMEOUT_MS`)를 그대로 씁니다).

- 자체 재시도 로직은 추가하지 않았습니다. 실패 시 `network.show({ retry })`로
  I-3을 띄우고, "다시 시도하기"는 같은 발화를 담아 C-5로 돌아가 아이가 다시
  "보내기"를 눌러야 재전송됩니다 — 자동 재전송·중복 제출 없음(요구 4).
- 대기 중 UI(THINKING)는 원래부터 그대로였고 이번 변경으로 더 오래 유지될
  뿐입니다. 백엔드 안전 폴백(`/respond` 실패 시 고정 대사)은 이미 일반 캐릭터
  응답으로 렌더링되고 있어 손댈 것이 없었습니다(요구 3).
- 아이 발화 원문을 새로 로깅하는 곳은 없습니다 — 실패 시
  `console.error("[play] 발화 제출 실패", error)`는 에러 객체만 남기고
  `text`/`sttRawText`는 넘기지 않습니다(요구 5).
