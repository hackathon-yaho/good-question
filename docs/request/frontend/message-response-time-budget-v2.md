# 대화 응답 시간 예산 v2 검증 요청

> **대체됨**: [v3](message-response-time-budget-v3.md)를 정본으로 사용한다.

- **요청자**: AI 파트
- **작성일**: 2026-08-15
- **우선순위**: 필수

## 배경

AI 서버 정책이 대화 엔드포인트별 Worker 내부 9초·백엔드 연결 10초·최대 10회로 바뀌었다.
`POST /api/sessions/{sessionId}/messages`는 `/analyze`와 `/respond`를 순서대로 호출할 수 있어,
두 호출 모두 최대로 지연될 때 최대 18초가 걸릴 수 있다. 기존 문서의 15초 보장은 더 이상
성립하지 않는다.

## 요구사항

1. 실제 `submitUtterance` 경로에 15초 이하에서 요청을 취소하는 `AbortController`, 타이머,
   프록시 제한이 없는지 확인한다.
2. 없다면 코드 변경 없이 검증 결과만 이 문서의 완료 조건으로 남긴다.
3. 있다면 임의로 시간을 늘리지 말고, 백엔드·AI와 함께 실제 측정값을 확인한 뒤 최소 변경 PR을 제안한다.
4. AI 최종 실패는 백엔드 안전 폴백으로 정상 응답되므로, 이를 네트워크 오류 팝업으로 바꾸지 않는다.

## 제약

- API 요청/응답 스키마와 화면 문구를 바꾸지 않는다.
- 음성(STT/TTS) 시간 제한은 별도 경로이므로 이 요청 범위가 아니다.
- 불필요한 타이머·재시도 코드를 추가하지 않는다.

## 완료 조건

- [ ] `POST /messages` 클라이언트 경로의 실제 중단 시간과 근거 파일을 공유한다.
- [ ] 18초 지연을 포함한 통합 실측 결과를 팀에 공유한다.
- [ ] 변경이 필요할 때만 별도 최소 변경 PR을 연다.
