# 아바타 상점 — 보유 아바타 노출 + 구매 엔드포인트

- **요청자**: 프론트엔드 (eungbin)
- **작성일**: 2026-08-16
- **업데이트**: 2026-08-16 — 프론트 구현 완료 후 명세 확정 (에러 코드 확정, 무료
  아바타 미노출·구매 확인창 등 화면 변경 반영). 아래 계약대로 주시면 프론트
  수정 없이 바로 붙습니다.
- **우선순위**: 선택 (프론트는 필드/엔드포인트가 없어도 정상 동작합니다 — 상점 전체가
  "아직 아무것도 못 샀다"로 보일 뿐입니다)

## 배경

별가루(`starDust`)는 이야기 완료 시 +100 적립되지만 지금은 쓸 곳이 없습니다
([O-18](../../product/prd.md), "사용처 없음"). 팀 논의로, 기존 무료 아바타 6종
(`color1`~`color6`)은 그대로 두고 **새로 추가하는 아바타만 별가루로 구매**하는
상점을 만들었습니다.

`avatarId`는 이미 검증하지 않는 값이라([backend/docs/decisions.md](../../../backend/docs/decisions.md) ·
`children.avatar_id` 컬럼 관련 결정) 새 아바타 id 자체는 백엔드 스키마 변경 없이
추가할 수 있습니다. 다만 "누가 어떤 아바타를 샀는지"와 "별가루 차감"은 서버가
들고 있어야 새로고침·다른 기기에서도 유지됩니다.

화면은 다음과 같이 구현되어 있습니다 (백엔드 계약과 무관한 참고용입니다):
- 상점(`/shop`, 사이드바 메뉴)에는 **무료 6종을 진열하지 않습니다** — 살 게
  없어서입니다. 유료 아바타만 별가루 아이콘 + 가격으로 표시하고, 눌러도
  바로 사지 않고 "○○를 데려올까요?" 확인창을 먼저 띄웁니다.
- 상점은 **구매만** 합니다. 실제로 바꿔 쓰는 것(장착)은 F-1 프로필의 별도
  아바타 변경 모달이 맡습니다 — 아래 3번 참고, 새 엔드포인트가 필요 없습니다.
- 현재 프론트 카탈로그(`frontend/src/lib/shop-catalog.ts`)는 실제 일러스트를
  받은 9종(늑대·햄스터·펭귄·코알라·숲여우·요정토끼·판다·유니콘고양이·천사고양이,
  150~350)입니다. `avatarId` 문자열 자체는 언제든 바뀔 수 있고 백엔드는 이
  목록을 들고 있을 필요가 없습니다 — 2번의 트레이드오프 항목 참고.

## API 명세

### 1. 보유 아바타 목록 — `GET /api/mypage`

응답의 `child` 객체에 필드 1개를 **추가**합니다. 기존 필드는 그대로입니다.

| 필드 | 타입 | 필수 | 설명 |
| --- | --- | --- | --- |
| `ownedAvatarIds` | string[] | 선택 | 이 아이가 상점에서 구매한 아바타 id 목록 |

```json
{
  "child": {
    "id": "c_01H...",
    "name": "지우",
    "avatarId": "color2",
    "age": 8,
    "starDust": 300,
    "ownedAvatarIds": ["shop1"]
  }
}
```

필드가 없으면 프론트는 상점의 유료 아바타를 전부 "미구매"로 취급합니다 —
`starDust` 필드를 옵셔널로 둔 것과 같은 원칙입니다.

### 2. 구매 전용 — 신규 `POST /api/children/{childId}/avatar-purchases`

⚠️ **이 엔드포인트는 구매만 합니다. 장착(현재 아바타 변경)은 하지 않습니다.**
상점은 잠금 해제 전용 화면이고, 실제로 바꿔 쓰는 것은 F-1 프로필의 별도
아바타 변경 모달이 맡습니다 (아래 3번 참고, 새 엔드포인트가 필요 없습니다).

**요청**

```json
{ "avatarId": "shop1", "price": 150 }
```

| 필드 | 타입 | 필수 | 설명 |
| --- | --- | --- | --- |
| `avatarId` | string | Y | 구매할 아바타 id |
| `price` | integer | Y | 차감할 별가루 양 (아래 참고) |

**성공 응답**

```json
{ "starDust": 150, "ownedAvatarIds": ["shop1"] }
```

**동작 및 에러 코드** — 프론트가 코드별로 분기해서 보여줄 문구가 다르니
**아래 문자열 그대로** 내려주세요 (`common/global/ErrorCode.java`에 추가).

| 상황 | 코드 | 프론트가 하는 일 |
| --- | --- | --- |
| 잔액 부족 (`starDust < price`) | `INSUFFICIENT_STAR_DUST` | 토스트 "별가루가 부족해요." |
| 이미 보유했거나 무료 6종 | `INVALID_REQUEST` (기존 코드) | 토스트 "적용하지 못했어요." |
| 존재하지 않는 `avatarId` | `NOT_FOUND` (기존 코드) | 토스트 "적용하지 못했어요." |

성공이면 `price`만큼 `starDust`를 차감하고 `ownedAvatarIds`에 `avatarId`를
추가합니다. **아이의 현재 아바타(`avatarId`)는 바꾸지 않습니다.**

⚠️ **트레이드오프 하나 짚어둡니다**: `avatarId`를 검증하지 않는 기존 정책과
같은 이유로, 이번 요청도 **`price`를 프론트가 보낸 값 그대로 신뢰해서
차감**하는 걸 전제로 했습니다. 테스트 단계라 수용 가능한 단순화지만, 클라이언트가
가격을 조작해 더 싸게 살 수 있다는 뜻이기도 합니다. 실서비스로 가게 되면
서버가 자체 가격 테이블을 갖고 `avatarId`로 가격을 조회하는 편이 안전합니다.

### 3. 장착(아바타 변경) — 새 엔드포인트 없음

F-1 프로필에서 아이가 자신이 보유한 아바타로 바꾸는 동작은 **기존
`PATCH /api/children/{childId}`** (`{ avatarId }`)를 그대로 씁니다 — 아이 등록,
H-2 보호자 인라인 편집과 같은 엔드포인트입니다. 이미 구현돼 있고 `avatarId`를
검증하지 않으므로 백엔드가 새로 할 일은 없습니다. 프론트가 보유 목록
(`ownedAvatarIds`)에서 고른 값만 보내도록 화면 쪽에서 막습니다.

## 확인 방법

`frontend`에서 `npm run verify`의 `shop` 스위트가 mock 모드로 전체 플로우
(구매 확인창 → 구매/취소 → 잔액 부족 상태 → 프로필에서 장착)를 확인합니다.

**실 백엔드 연동도 2026-08-16에 직접 확인했습니다** — 로컬로 백엔드를 띄우고
(`docker-compose up -d` + `./gradlew bootRun`) `?api=backend` + dev-login으로
실제 화면을 통해: 아이 등록 → 상점 구매(성공/잔액부족/무료·중복 거부 3종
에러 코드 전부 문서와 일치) → `GET /mypage`의 `ownedAvatarIds` 반영 →
프로필에서 `PATCH`로 장착 → 새로고침 후 영속까지 전부 확인했습니다.
추가로 손볼 것 없이 문서 그대로 맞았습니다.
