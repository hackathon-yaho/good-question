# 별가루 잔액·적립량 응답 노출 + 도입부 텍스트 길이

- **요청자**: 프론트엔드 (eungbin)
- **작성일**: 2026-08-13
- **우선순위**: 선택 (프론트는 필드가 없어도 정상 동작합니다)

## 배경

[화면 명세 B-1·F-1·D-7](../../spec/screens.md)의 별가루 UI를 구현했습니다.
[Q-12](../../open-questions.md)에서 "적립 규칙이 없어 MVP에서 빼는 것을 권장"했지만
[B-20](../../../backend/docs/decisions.md)에서 **재구성 완료 시 +100** 규칙이 정해졌으므로,
근거가 생긴 만큼 화면에 그렸습니다.

문제는 **그 값을 읽을 곳이 없다**는 것입니다. 적립 규칙은 서버에 있는데
잔액·적립량을 돌려주는 응답이 없습니다. 그래서 프론트는 지금 이렇게 처리합니다.

- `mock` 모드: 잔액과 적립량을 다 그립니다
- `backend` 모드: **필드가 없으면 칩과 애니메이션을 그리지 않습니다**
  (0으로 채우지 않습니다 — 0은 "안 모았다"는 거짓 정보가 됩니다)

즉 지금 실서버로 붙이면 별가루 UI가 통째로 사라집니다. 필드 2개만 실어주시면
프론트 수정 없이 바로 켜집니다.

## API 명세

### 1. 잔액 — `GET /api/home` · `GET /api/mypage`

응답의 `child` 객체에 필드 1개를 **추가**합니다. 기존 필드는 그대로입니다.

| 필드 | 타입 | 필수 | 설명 |
| --- | --- | --- | --- |
| `starDust` | integer | 선택 | 이 아이의 누적 별가루 잔액 |

```json
{
  "child": {
    "childId": "c_01H...",
    "name": "지우",
    "avatarId": "color2",
    "starDust": 300
  }
}
```

### 2. 적립량 — `POST /api/sessions/{sessionId}/activity/retelling`

| 필드 | 타입 | 필수 | 설명 |
| --- | --- | --- | --- |
| `earnedStarDust` | integer | 선택 | 이번 활동으로 적립된 양 (B-20 기준 100) |

```json
{
  "reportId": "r_01H...",
  "earnedStarDust": 100
}
```

## 프론트가 이 값으로 하는 일

| 값 | 화면 |
| --- | --- |
| `starDust` | B-1 홈 프로필 줄 · F-1 마이페이지의 별가루 칩 |
| `earnedStarDust` | D-7 완료 화면의 `+100` 표시와 별가루 낙하 애니메이션 |

## 확인 방법

`frontend`에서 `npm run verify`의 `wiring` 스위트가 두 응답을 가로채
필드가 있을 때 칩이 뜨고 없을 때 뜨지 않는지 확인합니다.

## 함께 요청 — 도입부(intro) 텍스트 길이

같은 파일에 묶어 적습니다. 별건이지만 둘 다 "값만 채우면 되는" 항목입니다.

### 무엇이 문제인가

C-1 도입부는 아이가 **"다음"을 눌러 한 문장씩 넘기는** 화면입니다.
지금 목 데이터는 3문장인데, 실제로 태블릿에서 눌러보면 3번 만에 이야기가 끝나
"이제 시작하나?" 싶은 순간에 대화로 넘어갑니다.

프론트 목 데이터는 6문장으로 늘려 확인했고 그 길이가 자연스러웠습니다.

### 요청

`GET /api/sessions/{sessionId}`의 intro 장면 텍스트를 **4~6문장** 분량으로 주시면
좋겠습니다. 문장 수를 프론트가 자르거나 합치지 않습니다 — 서버가 준 단위를
그대로 한 화면씩 넘깁니다.

- 한 문장은 **40자 이내**를 권합니다 (자막 폭 22ch에서 2줄 안에 들어옵니다)
- 문장 수 제한은 없습니다. 많으면 그만큼 넘깁니다

> AI 파트에서 생성하는 값이면 이 요청은 AI 쪽으로 전달 부탁드립니다.
