# 재생 불가 이야기 노출 — `comingSoon` 필드

- **요청자**: 프론트엔드 (eungbin)
- **작성일**: 2026-08-16
- **우선순위**: 선택 (프론트는 필드가 없어도 정상 동작합니다 — 모든 이야기를
  재생 가능으로 취급할 뿐입니다)

## 배경

이야기가 여러 편 더 늘어날 예정입니다. 다만 새로 추가되는 이야기들은 지금 있는
"방귀 뀌는 며느리"처럼 대화까지 만들어진 상태가 아니라, **홈 추천·이야기 목록에는
보이지만 상세 페이지에 들어가면 "준비 중이에요"만 뜨는** 전시 전용 이야기입니다
(장면 데이터가 아직 없어 실제로 재생하면 `/play`에서 깨집니다).

프론트는 이미 이 상태를 위한 자리를 만들어 뒀습니다 — `StoryDetail` 타입에
`comingSoon?: boolean` **선택 필드**가 있고(`frontend/src/lib/api/types.ts`),
현재는 목(mock) 카탈로그(`frontend/src/mocks/story-catalog.ts`)의 이야기 5편에만
이 값을 `true`로 채워서 씁니다. 이 필드가 응답에 있으면 이야기 상세(B-3) 화면이
**코드 변경 없이** 자동으로 "이야기 시작하기" 대신 "준비 중이에요" 비활성 버튼과
안내 문구를 보여줍니다.

⚠️ **지금 요청하는 것은 필드(스키마)입니다, 콘텐츠가 아닙니다.** 새로 추가될
이야기들의 실제 제목·줄거리·등장인물은 아직 최종본이 아니라서 지금은 프론트
목에 플레이스홀더로만 있습니다. 실제 콘텐츠가 정해지면 그 값을 별도로
전달하겠습니다 — 지금은 "장면이 없는 이야기를 어떻게 표현할지"만 맞추면 됩니다.

## API 명세

### `GET /api/stories`, `GET /api/stories/{storyId}`

두 응답 모두 이야기 객체(목록은 `stories[]` 항목, 상세는 최상위)에 필드 1개를
**추가**합니다. 기존 필드는 그대로입니다.

| 필드 | 타입 | 필수 | 설명 |
| --- | --- | --- | --- |
| `comingSoon` | boolean | 선택 | 장면(대화)이 아직 없어 재생할 수 없는 이야기인지 |

```json
{
  "id": "s_01H...",
  "title": "미운 아기 오리",
  "summary": "...",
  "coverImageUrl": null,
  "estimatedMinutes": 20,
  "difficulty": "보통",
  "topics": ["다름", "자기이해"],
  "comingSoon": true
}
```

필드가 없거나 `false`면 프론트는 지금처럼 재생 가능으로 취급합니다 — 기존
이야기(`방귀 뀌는 며느리`)에는 이 필드를 추가하지 않아도(또는 `false`로 줘도)
됩니다.

`coverImageUrl`·`characters[].imageUrl`은 지금처럼 계속 `null`로 주시면 됩니다.
프론트가 이야기 id/제목으로 정적 파일을 매핑해서 보여주는 기존 방식(표지·캐릭터
이미지 없음 → 텍스트/이니셜 폴백)을 그대로 씁니다 — 이 두 필드 때문에 새로
할 일은 없습니다.

## 데이터 모델

둘 중 편한 쪽으로 하시면 됩니다. 프론트는 응답 필드명(`comingSoon`)만 맞으면
됩니다.

| 옵션 | 방식 |
| --- | --- |
| A | `stories` 테이블에 `coming_soon` boolean 컬럼 추가 (기본 `false`) |
| B (권장) | 컬럼 추가 없이 응답 시점에 `story_scenes` 개수가 0이면 `comingSoon: true`로 계산 |

B를 권장하는 이유는 별도 컬럼을 안 만들어도 되고, 나중에 그 이야기의 장면이
실제로 만들어지면 자동으로 재생 가능 상태로 바뀌기 때문입니다(수동으로 플래그를
꺼줄 필요가 없습니다).

## 제약 조건

- 인증: 기존 이야기 목록·상세 조회 인증을 그대로 사용합니다.
- 새 이야기 레코드(제목·줄거리·등장인물 등 실제 콘텐츠) 자체는 이 문서의 범위가
  아닙니다 — 콘텐츠가 정해지면 별도로 전달합니다.
