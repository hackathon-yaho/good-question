# 반복 저정보 발화의 장면 종료 방지 요청

- **요청자**: AI 파트
- **작성일**: 2026-08-15
- **우선순위**: 필수

## 배경

실제 통합 테스트에서 아이가 `닥쳐` 또는 `싫어`만 세 번 반복하면 장면이 다음 이야기로 넘어갔다.
현재 `MessageServiceImpl`은 `SHORT`·`UNCLEAR`·`OFF_TOPIC`도 매번
`currentChildTurnCount + 1`로 계산하고, `ProgressJudge`는 `maxTurns` 종료를 GUIDED 판단보다 먼저
수행한다. 그래서 두 번째 저정보 발화에서 GUIDED가 선택되어도 세 번째에 `MAX_TURNS`로 닫힌다.

AI 서버는 이유·장면 내용 없는 짧은 거절·회피·공격(`싫어`, `몰라`, `닥쳐`)을 항상
`SHORT_RESPONSE` + `SHORT` + 빈 요소로 반환하도록 보정한다. 다만 장면 종료와 턴 예산은 백엔드
책임이므로, AI 프롬프트 변경만으로는 이 문제를 해결할 수 없다.

## 요구사항

1. `SHORT`·`UNCLEAR`·`OFF_TOPIC` 발화는 원문 메시지와 분석 기록에는 저장하되, 이야기 진행용
   `currentChildTurnCount`와 미션 `missionEngagedTurns`를 소모하지 않는다.
   - `VALID` 발화는 새 사고 요소가 없더라도 기존처럼 진행 턴을 소모한다.
   - 이 요청은 `PLAYFUL`의 현재 처리 규칙을 바꾸지 않는다.
2. 현재 발화가 저정보이고 `missingElements`가 남아 있으면, `MAX_TURNS` 또는 미션 최대 턴으로
   장면을 자동 종료하지 않는다.
3. 첫 저정보 발화는 현재의 짧고 비판하지 않는 반응(`NORMAL` + `unclearUtterance`)을 유지한다.
   두 번째 연속 저정보 발화부터는 `GUIDED`를 선택한다.
   - 직전 응답이 GUIDED라는 이유만으로, 현재 저정보 발화를 NORMAL로 되돌리지 않는다.
   - GUIDED는 같은 질문을 반복하지 않고 캐릭터의 남은 걱정 하나만 자연스럽게 제시한다.
4. 저정보 발화는 미션 자연 발동·강제 발동의 턴 수에도 포함하지 않는다.
5. 이 변경으로 새 enum·새 프론트 API·새 DB 컬럼을 만들지 않는다. 기존 `utteranceValidity`와
   `consecutiveLowInformationTurns`를 사용하고, 아이가 원하면 기존 "이야기 나가기"로 종료할 수 있다.

## 구현 제안

- `ProgressInput`에 현재 발화가 저정보인지 전달한다.
- 진행용 턴 수는 저정보가 아닐 때만 증가시킨다.
- `ProgressJudge`에서 저정보+missing 상태의 종료를 막고, 첫 발화/직전 GUIDED의 NORMAL 강제는
  현재 발화가 진행용 발화일 때만 적용한다.
- 미션 예산 갱신과 `MissionTrigger`에는 진행용 턴 수만 넘긴다.

## 검증 시나리오

필수 요소가 남아 있고 `maxTurns=3`인 대화 장면에서 아래 두 시나리오를 통합 테스트로 추가한다.

| 순서 | 입력 | 기대 모드 | 기대 결과 |
| --- | --- | --- | --- |
| 1 | `싫어` | NORMAL | 장면 미종료, 진행 턴 0 |
| 2 | `싫어` | GUIDED | 장면 미종료, 진행 턴 0 |
| 3 | `싫어` | GUIDED | 장면 미종료, 다음 장면 이동 없음 |
| 1~3 | `닥쳐` 반복 | 위와 동일 | AI의 `SHORT_RESPONSE` 결과를 사용 |
| 이후 | 장면 맥락의 `VALID` 발화 | 기존 규칙 | 진행 턴 1 증가, 정상 NORMAL/GUIDED/종료 판단 |

미션이 열린 장면에서도 저정보 반복이 `missionEngagedTurns`를 올리거나 미션을 자동 종료하지 않는
테스트를 추가한다.

## 제약

- `CLOSING`은 여전히 백엔드만 결정하고 AI 서버는 마지막 대사를 만들지 않는다.
- 아이를 꾸짖거나 욕설 자체를 화면에 다시 말하는 응답을 만들지 않는다.
- 단순히 `maxTurns` 숫자만 늘리는 방식은 허용하지 않는다.
