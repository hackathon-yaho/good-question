# 캐릭터 실제 대사 기반 8세 이하 추천 단어 v2 요청

- **요청자**: AI 파트
- **작성일**: 2026-08-16
- **우선순위**: 필수
- **대상**: 백엔드 파트

> **대체됨**: [장면별 학습 단어 추천 v1](scene-vocabulary-recommendation.md)의
> ‘장면 번호로 고정 추천’ 규칙은 적용하지 않는다. 이 문서를 정본으로 사용한다.

## 배경

현재 `recommendedWord`가 장면 번호만 보고 정해져, 방금 캐릭터가 말하지 않은 단어도 카드로
보인다. 이는 아이가 듣는 이야기와 단어 카드가 어긋나는 문제다. 추천 단어는 아이 발화나 과거
대사가 아니라 **이번 메시지에서 생성·확정된 캐릭터 대사**를 기준으로만 골라야 한다.

## API 계약

`POST /api/sessions/{sessionId}/messages`의 기존 선택 필드를 유지한다.

```json
{
  "characterMessage": "가족들이 놀랄까 봐 아직 말할 용기가 안 나.",
  "recommendedWord": {
    "word": "용기",
    "meaning": "어려워도 해 보려는 씩씩한 마음"
  }
}
```

- `recommendedWord`는 `{ word: string, meaning: string } | null`이다.
- `word`는 **이번 `characterMessage` 안에 연속된 문자열로 정확히 포함**될 때만 내려간다.
- 조건을 만족하는 8세 이하용 후보가 없으면 반드시 `null`이다. 단어를 억지로 넣기 위해
  AI 대사를 바꾸거나 LLM을 추가 호출하지 않는다.
- `meaning`은 초등 저학년이 이해할 쉬운 한 문장이다. 정답·평가·아이의 ‘모름’ 판단이 아니다.
- 아이 발화, 이전 턴·이전 장면 캐릭터 대사, 장면 번호만으로는 추천하지 않는다.

## 구현 범위

1. `SceneVocabulary.forSceneOrder(...)`처럼 장면만 보고 항상 한 단어를 넣는 경로를 제거한다.
2. Worker 응답 또는 안전 폴백으로 **최종 확정된 현재 `characterMessage`**를 만든 뒤,
   콘텐츠 검토를 받은 후보 목록 중 실제 포함된 단어가 하나 있을 때만 선택한다.
3. 후보가 여러 개면 콘텐츠가 정한 우선순위에서 하나만 선택한다. 후보 목록은 별도 상수로
   관리해도 되지만, 각 후보의 난이도·뜻풀이를 콘텐츠 담당자가 검토해야 한다.
4. 기존 `highlightWords`는 하위 호환을 위해 유지할 수 있으나 추천 카드의 근거로 사용하지 않는다.
   프론트는 v3 요청에 따라 대사 밑줄을 렌더링하지 않는다.
5. DB 마이그레이션, 새 LLM 호출, 세션 상태 변경, 아이 수준 추론을 추가하지 않는다.

## 완료 조건

- [ ] 캐릭터 대사에 없는 단어는 `recommendedWord`로 절대 내려가지 않는다.
- [ ] 현재 캐릭터 대사 안에 검토된 후보가 있으면 단어와 쉬운 뜻이 최대 하나 내려간다.
- [ ] 후보가 없는 정상 대사는 `recommendedWord: null`이며 대화·단어장·미션이 계속 동작한다.
- [ ] Worker 응답과 `character_closing` 폴백 각각에서 위 조건을 자동 테스트한다.
- [ ] 기존 메시지 API 스키마와 STT/TTS 경로가 바뀌지 않는다.
