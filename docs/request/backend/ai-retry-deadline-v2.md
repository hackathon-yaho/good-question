# AI 호출 재시도·시간 예산 v2 요청

> **대체됨**: 2026-08-16부터 [AI 호출 재시도·시간 예산 v4](ai-retry-deadline-v4.md)를
> 정본으로 사용한다. v2의 최대 3회 규칙은 적용하지 않는다.

- **요청자**: AI 파트
- **작성일**: 2026-08-15
- **우선순위**: 필수

## 배경

실제 OpenAI 모델 응답 실패가 즉시 `502 MODEL_UPSTREAM_ERROR`로 끝나, 일시적인 연결 오류나
구조화 출력 실패에도 아이의 대화가 바로 폴백되는 문제가 확인됐다. 팀 합의에 따라 AI 서버는
한 엔드포인트 요청 안에서 **전체 10초**, **최초 요청을 포함해 최대 3회**까지 재시도한다.

이 문서는 [AI 서버 연동 v1](ai-service-integration-v1.md)의 요청·응답 스키마를 바꾸지 않는다.
v1의 5초·재시도 0회 제약만 이 문서로 대체한다.

## 요구사항

1. AI 서버(`/analyze`, `/respond`)가 재시도를 전담한다.
   - `OPENAI_TIMEOUT_SECONDS=10`은 **한 HTTP 요청 전체**의 상한이다.
   - 최초 요청을 포함해 최대 3회만 시도한다. SDK의 자체 재시도는 `0`으로 유지한다.
   - 각 시도는 3초 이내, 시도 사이의 짧은 대기까지 포함해 10초를 넘기지 않는다.
   - 연결·타임아웃·429·모델 5xx, 비어 있거나 스키마에 맞지 않는 구조화 출력, 금지된 교사/채점 말투는 다음 시도를 허용한다.
   - 인증·요청 형식 오류처럼 재시도해도 바뀌지 않는 오류는 즉시 실패한다.
2. 최종 상태 코드는 AI 서버가 일관되게 반환한다.
   - 전체 시간 제한 초과 또는 3회 시간 초과: `504 MODEL_TIMEOUT`
   - 재시도 가능한 모델/출력 오류가 3회 모두 실패: `502 MODEL_UPSTREAM_ERROR`
   - 내부 토큰 불일치: `401 UNAUTHORIZED`, 요청 계약 위반: `422 INVALID_REQUEST` (재시도 대상 아님)
3. 백엔드는 `AI_SERVER_TIMEOUT_SECONDS` 기본값과 실환경 값을 **10초**로 둔다.
   - AI 서버의 요청 전체 제한과 같은 값이다. AI 서버는 시도당 최대 3초와 짧은 대기를 사용해
     세 번째 시도까지 10초 안에서 끝낸다.
   - 백엔드는 별도 AI 재시도를 추가하지 않는다. 중복 재시도로 비용과 지연이 늘어나는 것을 막는다.
   - 현재 main의 D-51은 이 값을 10초로 반영했다. 단, D-51의 "SDK `max_retries` 0→3" 서술은
     현재 AI 서버 구현과 다르다. SDK는 0회이고 AI 서버가 최대 3회를 제어하므로, 백엔드 문서만
     이 기준으로 정정한다.
4. 최종 502/504는 현재의 안전 폴백을 유지한다.
   - `/analyze` 실패: 빈 분석으로 정상 진행한다.
   - `/respond` 실패: 검수된 `character_closing`으로 장면을 종료한다.
   - 이 폴백은 프론트에 500 오류로 전달하지 않고, 정상 `POST /messages` 응답으로 완결한다.
5. 대화 요청의 최악 시간은 `/analyze` 10초 + `/respond` 10초 = 20초다. 프론트 15초 예산은
   더 이상 보장값이 아니므로, [프론트 검증 요청](../frontend/message-response-time-budget-v2.md)의
   결과가 나오기 전까지는 클라이언트 타임아웃을 새로 추가하거나 더 짧게 만들지 않는다.

## API 스키마

`POST {AI_SERVER_BASE_URL}/analyze`, `POST {AI_SERVER_BASE_URL}/respond`의 URL, 헤더
`X-Internal-Token`, JSON 요청·응답 스키마와 enum은 v1과 동일하다. 재시도 횟수나 내부 시도 번호를
응답 본문에 추가하지 않는다.

## 제약

- AI 서버는 상태·DB·이미지·STT/TTS를 소유하지 않는다.
- `OPENAI_API_KEY`와 `AI_SERVER_INTERNAL_TOKEN`의 실제 값은 문서·커밋·로그에 넣지 않는다.
- `/respond`의 `CLOSING` 호출은 여전히 금지이며, 실패 폴백용 `character_closing`은 백엔드가 조회한다.
