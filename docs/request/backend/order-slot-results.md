# 카드 순서 — 칸별 정오 (`slotResults`)

- **요청자**: 프론트엔드 (eungbin)
- **작성일**: 2026-08-13
- **우선순위**: 선택 (없어도 화면은 동작합니다. 아래 임시 동작 참조)

## 배경

D-2 카드 순서 배열에서, 오답일 때 **틀린 칸만** 빨간 테두리로 표시하고 맞은 칸은
지금 테두리를 유지하기로 했습니다. 아이가 무엇을 옮겨야 하는지 알 수 있습니다.

## 문제 — 프론트는 어느 칸이 틀렸는지 알 수 없습니다

`POST /api/sessions/{id}/activity/order` 응답은 이렇습니다.

| 필드 | 내용 |
| --- | --- |
| `isCorrect` | 배치 **전체**의 정오 |
| `attemptCount` | 시도 횟수 |
| `correctOrder` | **3회째 오답에만** 온다 |

1·2회째에는 "틀렸다"만 알 수 있고 어느 칸인지는 모릅니다. `hintCardId` 같은 필드도
없습니다. 특정 칸을 짚으려면 프론트가 정답을 알아야 하는데, **정답 판정은 서버만
한다**는 원칙(PRD 8.11)에 어긋납니다.

그래서 지금은 **배치 전체**에 빨간 테두리를 넣고 있습니다.

## API 명세

### `POST /api/sessions/{sessionId}/activity/order`

응답에 필드 1개를 **추가**합니다.

| 필드 | 타입 | 필수 | 설명 |
| --- | --- | --- | --- |
| `slotResults` | boolean[] | 선택 | 제출한 순서대로 각 칸이 **정답 위치인지** |

```json
{
  "isCorrect": false,
  "attemptCount": 1,
  "slotResults": [true, false, false, true]
}
```

- 길이는 `submittedOrder`와 같습니다 (카드 4장)
- 인덱스는 **제출한 배치의 칸 번호**입니다. `slotResults[1] === false`는
  "2번 칸에 놓인 카드가 그 자리가 아니다"입니다
- **`isCorrect: true`이거나 3회째일 때는 보내지 않아도 됩니다.** 프론트가 그때는
  표시하지 않습니다 (아래 참조)

## 왜 이 형태인가 — 정답을 역산할 수 없습니다

정답 순서를 내려보내지 않고 "이 칸이 맞는지"만 알려주므로, 프론트는 여전히 정답을
모릅니다. **정답 판정은 서버만 한다는 원칙을 깨지 않고** 요구를 만족하는 최소
필드입니다.

## 프론트가 이 값으로 하는 일

| 상황 | 표시 |
| --- | --- |
| `slotResults[i] === false` | 그 칸만 `border-danger` |
| `slotResults[i] === true` | **현재 테두리 유지.** 초록 테두리를 새로 넣지 않는다 |
| `slotResults`가 없음 | 배치 전체를 `border-danger` (지금 동작) |
| 3회째 (`correctOrder`가 온 경우) | 어느 쪽이든 **표시하지 않는다** |

- 맞은 칸에 초록을 넣지 않는 이유 — 정답 **개수**를 세는 화면이 됩니다.
  점수·등급 표시는 금지입니다 (PRD 10.3)
- 3회째에 표시하지 않는 이유 — 다음 시도가 없는데 지적만 남습니다.
  정답 순서를 보여주며 다음 단계로 넘어가는 판입니다 (D-10)
- 어느 경우에도 **"틀렸어요"·"실패" 같은 문구는 쓰지 않습니다.** 테두리는
  "다시 볼 곳" 표시이고 판정 문구가 아닙니다

## 없을 때의 임시 동작 (지금 구현되어 있음)

```tsx
const wrong = card && (slotResults ? slotResults[index] === false : mismatched);
```

필드가 오면 칸 단위로, 안 오면 배치 전체로 그립니다.
**백엔드를 기다리며 화면이 멈추지 않습니다** — 필드를 실어주시면 프론트 수정
없이 바로 켜집니다.

## 확인 방법

`frontend`에서 `npm run verify`의 `activity` 스위트가 두 경우를 모두 확인합니다.
목 서버는 1·2회째에 `slotResults`를 싣고, `wiring` 스위트는 필드가 없는 응답에서
배치 전체가 표시되는지를 확인합니다.
