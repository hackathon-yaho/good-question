# 에셋 요구 명세

화면을 그리는 데 필요한 **이미지·텍스트 에셋**의 전체 목록, 규격, 수령 상태, 없을 때의 대체 계획입니다.

| 항목 | 내용 |
| --- | --- |
| 작성일 | 2026-08-10 |
| 근거 | [screens.md](screens.md)에 명시된 픽셀값에서 역산 |
| 상태 | 규격은 **팀 제안** (주최측·디자인 합의 전) |

## 왜 이 문서가 필요한가

이야기 일러스트는 주최측이 구글 드라이브로 제공 예정이고 아직 수령 전입니다.
[작업 분장 2.2](../team/roles.md)는 **"수령 전까지 플레이스홀더로 진행하되, 이미지 규격(비율·해상도)을
미리 정해두면 교체가 수월하다"** 고 권고했지만 실제 값을 정해두지 않았습니다.

규격을 먼저 정해두지 않으면 두 번 일합니다. 플레이스홀더를 규격에 맞춰 넣어두면
실제 파일이 도착했을 때 **파일만 갈아끼우면** 됩니다.

### 수령분 상세 (2026-08-13)

원본은 크고 화면은 작습니다. 원본을 그대로 `<img>`에 걸면 태블릿 첫 로딩이
느려지므로, 표시 크기의 2배로 줄인 webp를 만들어 그걸 씁니다.

| 파일 | 원본 | 배포본 | 용량 |
| --- | --- | --- | --- |
| 아바타 6종 | `public/characters/1~6.png` 1024² (7.2MB) | `public/avatars/{chick,fox,bear,rabbit,turtle,cat}.webp` 256² | 11~16KB |
| 로고 | `public/logo.png` 1280×458 | `logo-symbol.webp` 256² · `logo-wordmark.webp` 640×229 | 13KB · 39KB |

- **원본 png는 커밋하지 않습니다** (`.gitignore` — 아바타 6장과 로고 1장). 웹에 쓰이는
  것은 변환 결과 webp뿐이고, 코드가 원본을 참조하지 않습니다. 다시 만들어야 하면
  원본을 받아 변환 절차를 한 번 더 돌립니다
- 아바타는 배경이 종이 질감이라 **투명 처리를 하지 않았습니다.** CSS 원형 마스크로
  잘라 씁니다 — 알파 채널을 파려면 6장을 손으로 따야 하고, 원형으로 가리면 결과가 같습니다
- 로고 원본은 워드마크 단독이라 심볼이 따로 없습니다. **왼쪽 Q 기호를 크롭해**
  심볼 파일을 만들었습니다 (A-1 스플래시·사이드바용)

> **로고는 제약이 아니라 에셋입니다.** [PRD 1.3](../product/prd.md)이 "상표권 등록 완료, 변경 불가"라고
> 적어둔 탓에 제약으로만 읽히기 쉬운데, [A-1·A-2·사이드바](screens.md)에 실제로 렌더링해야 하는
> 파일입니다. 요청 목록에서 빠뜨리기 쉬운 항목입니다.

## 2. 규격 제안

전부 [screens.md](screens.md)에 적힌 표시 크기에서 역산했습니다. 화면 기준 해상도는
`ImmersiveShell` 1280×800 (C·D), 그 외 1440×900입니다.

### 2-1. 장면 배경 일러스트

| 화면 | 표시 영역 | 계산 |
| --- | --- | --- |
| C-1 도입 | 풀브리드 | 1280 × 800 |
| C-2~C-7 장면 | 좌 60% | 768 × 800 |

**제안: 1280×800 원본 1장 (16:10)** — 좌측 768×800을 **세이프 에어리어**로 두고 핵심 요소를 그 안에 배치합니다.
그러면 도입(풀브리드)과 장면(좌 60% 크롭)에 같은 파일을 쓸 수 있습니다.

```
┌─────────────────────────┬──────────┐
│  세이프 에어리어 768×800  │ 잘리는 영역 │   1280×800
│  (핵심 요소는 여기)       │  512×800  │
└─────────────────────────┴──────────┘
   C-2~C-7은 왼쪽만 사용        C-1은 전체 사용
```

필요 장수: 도입 1 + 전개 4 = **5장** (`sc_banggui_01/02/04/06/08`)

> 대화 장면(`03/05/07/09`)은 직전 전개의 배경을 유지합니다.
> [screens.md C-3](screens.md)이 "장면 일러스트 (정지, 85% 밝기)"라고 한 것이 이것입니다.

### 2-2. 캐릭터 초상 (원형 마스크)

| 화면 | 표시 크기 |
| --- | --- |
| C-3 / C-6 발화 중 | 96px |
| C-12 장면 전환 | 120px |
| C-2 실루엣, D-3 | 140px |
| I-1 마이크 권한 | 160px |

최대 160px × 2배 = 320px.

**제안: 320×320 정사각, 투명 PNG** — 원형으로 마스킹되므로 얼굴이 중앙 정원 안에 들어와야 합니다.
캐릭터 3인 (`며느리`, `시아버지`, `마을 이장`) = **3장**.

> C-2의 그레이스케일 실루엣은 CSS `filter: grayscale(1)`로 처리하면 별도 파일이 필요 없습니다.
> [PRD A-03](../product/prd.md) 캐릭터 마음 변화(선택)를 구현하면 표정별로 장수가 늘어납니다.

### 2-3. 캐릭터 전신·단체

| 화면 | 표시 크기 |
| --- | --- |
| D-1 활동 인트로 (단체) | 380px |
| D-7 세션 완료 (단체) | 360px |
| H-4 고객센터 | 80px |
| H-5 이용 안내 | 110px |

**제안: 800×800 투명 PNG** — 단체 컷 1장 + 개별 전신 3장.

### 2-4. 이야기 표지

| 화면 | 표시 |
| --- | --- |
| B-3 대형 표지 | 좌 45% × 전체 높이 = 648 × 900 (**2:3 세로**) |
| B-1 이어하기 히어로 | 좌 58% 카드 내 (가로) |
| B-2 카드 그리드 3열 | 가로 |
| G-1 리포트 목록 | 64px 썸네일 |

⚠️ **비율이 화면마다 다릅니다.** B-3은 세로 2:3, B-1·B-2 카드는 가로입니다.
한 파일로 둘 다 쓰려면 `object-fit: cover` 크롭이 필요하고, 그러면 세로형에서 좌우가,
가로형에서 위아래가 잘립니다.

**제안**: **1440×1080 (4:3) 원본 1장** + B-3만 `object-position`으로 중앙 세로 크롭.
또는 세로·가로 2장을 따로 받는 것이 안전합니다. → [Q-19](../open-questions.md)

### 2-5. 말하기 후 활동 카드

| 화면 | 표시 크기 | 비율 |

**제안: 480×360 (4:3) 4장** — 전개1~4 이미지에서 크롭합니다.
[PRD 7.8](../product/prd.md)이 "카드는 전개1~4에 각각 대응하며, 각 카드는 해당 전개의 이미지와 함께 표시"로
확정해 두었으므로 §2-1의 배경 5장 중 전개 4장에서 파생됩니다. **별도 수령 불필요.**

### 2-9. 파일 형식·용량

- **형식**: 사진형 배경은 **WebP**, 투명 필요한 캐릭터·로고는 **PNG** 또는 **SVG**
- **용량**: 배경 1장당 **300KB 이하** 권장
- **이유**: 지원 기기 1순위가 태블릿이고 백엔드가 Render 무료 티어입니다. 프론트는 Vercel 무료 티어로 정적 서빙되므로 이미지 용량이 첫 로딩 체감을 지배합니다
- **@2x 대응**: 레티나 태블릿(iPad)을 고려해 위 제안 수치는 이미 표시 크기의 2배입니다

## 3. 없을 때 대체 계획

에셋을 기다리며 멈추지 않기 위한 폴백입니다. **전부 구현 가능하고, 파일 도착 시 교체만 하면 됩니다.**

### 3-1. 이야기 일러스트

§2 규격의 빈 박스를 CSS로 만들고 장면 이름을 텍스트로 얹습니다.

```
┌──────────────────────────┐
│                          │
│      [전개1 배경]         │   background: var(--color-primary-soft)
│      768 × 800           │   중앙에 장면 ID 텍스트
│                          │
└──────────────────────────┘
```

캐릭터 초상은 이니셜 원형(`며`, `시`, `이`)으로 대체합니다.
**규격에 맞춰 넣어두는 것이 핵심입니다.** 그러면 레이아웃이 흔들리지 않습니다.

### 3-2. 로고

`굿퀘스천` 텍스트 로고타입 (`--font-family` 700, `--color-primary`).
[screens.md A-1](screens.md)의 "말풍선+Q 96px" 자리에 텍스트를 넣습니다.

> [PRD 1.3](../product/prd.md)은 "더 나은 제안이 있을 경우 변경할 수 있다"고 했으므로
> 팀이 임시 심볼을 만들어도 됩니다. 다만 서비스명 "굿퀘스천"은 상표권 등록 완료로 **변경 불가**입니다.

### 3-3. 아이 아바타

이름 첫 글자 + 색상 6종 원형 아바타. `avatar_id`에 색상 키(`fox`, `rabbit` 대신 `color1`~`color6`)를 저장하면
나중에 일러스트로 교체할 때 매핑만 바꾸면 됩니다.

### 3-4. 약관 전문

"정식 서비스 시 제공됩니다" placeholder + 항목 제목만. 동의 체크박스 동작은 정상 구현합니다.

> **아동 개인정보 처리 동의는 요건**입니다 ([PRD 10.3](../product/prd.md)).
> 전문이 없어도 `child_consents` 레코드 생성과 세션 차단 로직은 반드시 동작해야 합니다.
> 문구만 placeholder이고 기능은 placeholder가 아닙니다.

### 3-5. 효과음

[screens.md 1-5](screens.md)의 `CHILD_TURN` 딩동 효과음. 무료 음원(CC0)으로 대체합니다.

> 브라우저 자동재생 정책 때문에 **첫 사용자 제스처 이후에만** 재생됩니다.
> I-1 "마이크 켜기" 클릭을 그 제스처로 활용하면 됩니다 ([screens.md C-4 체크리스트](screens.md)).

### 3-6. 미션 2 친구 카드 그림 4종 (2026-08-13 추가)

[C-11](screens.md) 미션 2의 친구 카드 4장에 들어가는 그림입니다.

| 항목 | 값 |
| --- | --- |
| 대상 | 목소리가 큰 친구 · 질문이 많은 친구 · 힘이 센 친구 · 조용한 친구 |
| 규격 제안 | **256×256 정사각** (표시 98~112px의 2배) · webp |
| 상태 | ❌ 미수령 |
| 폴백 | 규격 자리를 지키는 색면 + "그림 준비 중" |

> **아이 아바타 6종을 돌려쓰지 않았습니다.** 어느 동물이 "목소리가 큰 친구"인지는
> 임의 배정이고, 나중에 실제 그림이 오면 어긋납니다. 아바타는 아이 자신을 가리키는
> 그림이기도 해서 역할이 다릅니다.
