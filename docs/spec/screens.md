## 이 문서의 목적

Stitch로 생성한 화면 시안을 실제 웹으로 구현할 때, 화면마다 "무엇을 보여주고 / 언제 바뀌고 / 어떤 데이터를 물고 / 무엇을 서버에 보내는지"를 확정하기 위한 문서입니다.

디자인 시안과 화면 ID가 1:1로 대응합니다. 시안을 보면서 이 문서를 같이 읽으면 됩니다.

> ⚠️ **PRD와의 범위 차이**: 이 문서는 화면 48개를 다루고, [작업 분장 2.1](../team/roles.md)은 필수 화면 11개를 다룹니다.
> 여기의 상당 부분(힌트 시트, 단어장, 별가루, 리포트)은 PRD 기준으로 **선택 또는 범위 밖**입니다.
> 우선순위 판단은 [PRD 11장](../product/prd.md)을, 문서 간 충돌은 [../open-questions.md](../open-questions.md)를 따릅니다.

## 0. 읽기 전에 — 가장 중요한 3가지

### 0-1. 화면 ID ≠ 페이지(URL)

이걸 오해하면 구조를 처음부터 다시 짜야 합니다.

| 구분 | 화면 ID | 실제 구현 |
| --- | --- | --- |
| 독립 페이지 | A-1~A-6, B-1~B-3, E-1, F-1, G-1~G-4, H-1~H-5 | 각각 별도 URL |
| 한 페이지의 상태 | C-2 ~ C-7 | `/play/{sessionId}` 단일 페이지의 상태 전환 |
| 한 페이지의 상태 | D-1 ~ D-7 | `/activity/{sessionId}` 단일 페이지의 단계 전환 |
| 오버레이/모달 | B-4, C-8~C-11, C-13, E-2, H-6, H-7, I-1, I-4 | 부모 화면 위에 띄움, URL 변경 없음 |

즉 **이야기 진행 구간은 페이지 이동이 없습니다.** 좌측 일러스트 영역과 우측 대화 패널은 계속 살아 있고, 그 안의 상태만 바뀝니다. 페이지를 새로 그리면 TTS가 끊기고 애니메이션이 튑니다.

### 0-2. 화면 상태는 서버가 정한다

`NORMAL` / `GUIDED` / `CLOSING` 같은 진행 모드는 서버가 규칙으로 확정해서 내려줍니다. 프론트가 발화 내용을 보고 판단하지 않습니다.

카드 순서 정답 여부도 마찬가지로 서버가 계산합니다. **프론트는 정답 순서를 알지 못합니다.**

프론트의 역할은 서버가 내려준 상태값을 화면 상태로 매핑하는 것까지입니다.

### 0-3. 음성 원본은 저장하지 않는다

마이크로 녹음한 오디오는 STT로 텍스트 변환 후 즉시 폐기합니다. 서버로 오디오 파일을 업로드하지 않습니다(STT 처리 목적의 일시 전송 제외).

화면에도 "목소리는 저장되지 않아요" 문구가 들어가 있으므로, 구현이 이 약속을 어기면 안 됩니다.

## 1. 공통 규약

### 1-1. 화면군별 레이아웃 셸(Shell)

프론트에서 레이아웃 셸 3종만 만들어두고 재사용하면 됩니다.

| 셸 이름 | 적용 화면 | 구조 |
| --- | --- | --- |
| `ImmersiveShell` | C, D 전체 | 1280×800 기준, 네비게이션 없음, 좌 60% / 우 40% 또는 풀브리드 |
| `SidebarShell` | B-1, B-2, E-1, F-1 | 좌측 고정 사이드바 240px + 메인 영역, 1440×900 |
| `CenteredShell` | A, B-3, G, H 전체 | 사이드바 없음, 중앙 정렬 컬럼(560~960px), 1440×900 |

> B-3(이야기 상세)만 B 그룹인데 `CenteredShell`이 아니라 좌우 스플릿 단독 레이아웃입니다.
> 표지 일러스트 45% + 정보 55% 구조라 셸을 공유하지 않습니다.

### 1-1b. 해상도 스케일링 — 구현 시 확정 (2026-08-10)

**크기 토큰은 전부 `rem`으로 둡니다. px로 박으면 해상도가 바뀔 때 비율이 무너집니다.**

실측으로 확인한 문제입니다. px 고정이던 시점의 마이크 버튼 / 우측 패널 폭 비율:

| 해상도 | 비율 |
| --- | --- |
| 1280×800 (설계 기준) | 35% |
| iPad mini 가로 1133×744 | 40% |
| 노트북 1920×1080 | **23%** |
| 태블릿 세로 820×1180 | **55%** |

오버플로는 없는데 **비율이 2.4배 드리프트**했습니다. 1920에서는 데드 스페이스가 커지고, 좁은 태블릿에서는 요소가 과대해집니다.

**해결: 화면군별 루트 스케일**

C·D는 좌우 60/40 고정 무대라 리플로우할 것이 없으므로 **통째로 비례 스케일**합니다.
A·B·G·H는 문서형이라 **16px 고정**입니다. 큰 모니터에서 보호자 본문이 커지면 조잡해집니다.

```css
:root { font-size: 16px }                    /* 문서형 A·B·G·H */

html[data-shell="immersive"] {               /* 몰입형 C·D */
  font-size: calc(
    clamp(13px, min(1.25vw, 2vh), 22px) * var(--kid-font-scale, 1)
  );
}
```

`min(1.25vw, 2vh)`로 **좁은 쪽을 기준**으로 잡습니다. 태블릿은 폭이, 넓은 모니터는 높이가 한계입니다.

| 해상도 | 루트 | 배율 | 대사 |
| --- | --- | --- | --- |
| 1280×800 | 16.0px | 1.00× | 32px |
| iPad mini 1133×744 | 14.2px | 0.89× | 28px |
| iPad Pro 12.9 1366×1024 | 17.1px | 1.07× | 34px |
| 노트북 1920×1080 | 21.6px | **1.35×** (상한) | 43px |

`rem`은 언제나 `<html>` 기준입니다. 셸 div에 `font-size`를 줘도 `rem`에는 반영되지 않으므로,
`ImmersiveShell`이 `<html>`에 `data-shell="immersive"`를 걸어야 합니다.

**세로 모드는 지원하지 않습니다.** 이 문서가 "패드 전체 화면", "좌 60% / 우 40%"를 전제하므로
스케일링으로 풀리지 않습니다. `ImmersiveShell`이 `(orientation: portrait)`을 감지해
"화면을 옆으로 돌려줘" 안내로 대체합니다.

> `--kid-font-scale`은 [C-13](#c-13-일시정지-시트)의 글씨 크기 설정이 곱합니다.
> px 고정이던 때는 구현할 수 없던 기능인데 rem 전환으로 살아났습니다.

### 1-3. 타이포 스케일

| 용도 | 크기/굵기 | 적용 |
| --- | --- | --- |
| 캐릭터 대사 | 30~32px / 700 | C 화면 말풍선 |
| 내레이션 자막 | 28~34px / 500 | C-1, C-2 하단 자막 |
| 아이 화면 버튼 | 24~26px / 700 | C, D 주요 CTA |
| 아이 화면 본문 | 20~22px / 400 | C, D 보조 텍스트 |
| 보호자 제목 | 26~28px / 700 | A, G, H |
| 보호자 본문 | 15~17px / 400 | A, G, H |

> **아이 화면에서 지켜야 할 것**: 대사는 한 번에 한 문장만, 줄당 최대 22자.
> 두 문장을 한 번에 띄우면 아이가 읽는 속도를 못 따라갑니다.
>
> 위 px 값은 **1280×800 기준값**입니다. 구현은 `rem`으로 두고 §1-1b에 따라 비례 스케일합니다.
> `--text-dialogue: 1.9375rem` (= 31/16). 줄당 22자는 `max-w-[22ch]`로 잡으면 스케일과 함께 따라갑니다.

### 1-5. 대화 상태 4색 규칙 — 이 서비스의 핵심 UX

아이가 "지금 내가 말할 차례인가?"를 헷갈리지 않게 하는 것이 이 서비스의 성패입니다. 아래 4가지 상태는 시각 신호가 서로 확연히 달라야 합니다.

| 상태 코드 | 화면 신호 | 사운드 | 마이크 |
| --- | --- | --- | --- |
| `CHARACTER_SPEAKING` | 캐릭터 아바타에 파란 링(`--color-info`) 맥동 + 자막 타이핑 | TTS 재생 | 비활성(회색) |
| `CHILD_TURN` | 화면 전체 테두리 10px 주황 glow 맥동 + 마이크 180px 확대 + "이제 말해 볼까?" | 딩동 효과음 | 활성 |
| `TRANSCRIBING` | 회색 웨이브폼 + "듣고 있어요…" | 없음 | 녹음 중 |
| `THINKING` | 캐릭터 위 점 3개 로더 + "음… 생각 중이야" | 없음 | 비활성 |

### 1-7. 사고 요소(Thinking Element) 표기 매핑

서버는 영문 코드로 내려줍니다. **아이 화면에는 절대 영문 코드를 노출하지 않습니다.**

| 서버 코드 | 아이 화면 표기 | 보호자 화면 표기 |
| --- | --- | --- |
| `EMOTION` | 마음 | 감정 표현 |
| `EMPATHY` | 마음 | 공감 |
| `REASON` | 이유 | 이유 말하기 |
| `PERSPECTIVE` | 생각 | 다른 사람 입장 |
| `SOLUTION` | 방법 | 해결 방법 |
| `DECISION` | 생각 | 판단·선택 |
| `RESULT` | 생각 | 결과 예상 |
| `REQUEST` | 방법 | 요청하기 |

아이 화면에서는 8종을 **4개 그룹(마음/이유/생각/방법)** 으로 묶어 별 뱃지로 표시합니다. 8개를 다 보여주면 아이에게 과부하입니다.

> 보호자 화면 표기는 [보호자 리포트 가이드](../reference/guardian-report-guide.md) 4절의
> "내부 분석 태그를 보호자 화면에 직접 노출하지 않는다" 규칙과 일치합니다.

```
/                          → A-1 스플래시 (인증 확인 후 리다이렉트)
/login                     → A-2 로그인
/onboarding/consent        → A-3 약관 동의
/onboarding/child          → A-4 아이 프로필 등록
/profiles                  → A-5 아이 프로필 선택

/home                      → B-1 홈

                             └ B-4는 이 위의 모달

                             └ C-8~C-11, C-13은 이 위의 오버레이

/parent/reports            → G-1 리포트 목록
/parent/reports/{sessionId}?tab=analysis|quotes|guide
                           → G-2 / G-3 / G-4 (탭 쿼리로 구분)

/parent/settings           → H-1 설정
/parent/settings/children  → H-2 아이 프로필 관리
/parent/notices            → H-3 공지사항
/parent/support            → H-4 고객센터
/parent/guide              → H-5 이용 안내
                             └ H-6, H-7은 모달

(I-1, I-4는 /play 진입 전 오버레이, I-2는 /play 내부 상태, I-3은 전역 오버레이)
```

### 라우트 가드

| 경로 | 진입 조건 | 미충족 시 |
| --- | --- | --- |
| `/home`, `/stories/*`, `/wordbook`, `/mypage` | 로그인 + 아이 선택됨 | `/profiles`로 |
| `/play/*`, `/activity/*` | 위 조건 + 해당 아이의 `child_consents` 유효 + 마이크 권한 허용 | 동의 없으면 진행 불가 안내, 권한 없으면 I-1 |
| `/parent/*` | 로그인 | `/login`으로 |
| `/onboarding/*` | 로그인 | `/login`으로 |

> **동의가 없거나 철회된 아이는 새 이야기 세션을 시작할 수 없습니다.** (`child_consents` 규칙)
> 이 가드가 빠지면 요건 위반입니다. 프론트 가드만으로 부족하고 서버에서도 막아야 합니다.
> ([작업 분장 3.4](../team/roles.md))

## 3. 전체 화면 흐름도

### 3-1. 최상위 흐름

### 3-2. 이야기 진행 상태 전환 (`/play/{sessionId}` 내부)

## I. 시스템 / 예외

### I-1 마이크 권한 요청

형태: B-3 위 모달 600px · 닫기 버튼 없음

**UI**: 마이크 든 캐릭터 160px / "목소리로 이야기할 거예요" / "마이크를 켜야 친구와 이야기를 시작할 수 있어요. / 목소리는 저장되지 않고 글자로만 바뀌어요." / 방패 아이콘 안내 / "마이크 켜기" 단일 버튼 / 헬퍼 "이야기를 시작하려면 마이크 허용이 꼭 필요해요."

**동작**

```
"마이크 켜기" 클릭
  → navigator.mediaDevices.getUserMedia({ audio: true })
     ├─ resolve → C-1로 진행
     └─ reject  → I-4로 전환
```

> **마이크는 필수 정책**: 건너뛰기 옵션 없음. 이 화면을 벗어나는 유일한 방법은 브라우저 뒤로가기입니다.

> 구현: `MicGate`가 I-1·I-4 판단을 한곳에서 한다. `/play` 직접 진입과 B-3
> "이야기 시작하기"가 같은 판단을 써야 하기 때문이다.
> `getUserMedia`로 얻은 스트림은 **즉시 끊는다.** Web Speech API가 자기 스트림을
> 따로 열고, 붙잡고 있으면 탭에 녹음 표시가 계속 떠서 음성 미저장 정책이 의심받는다.

## 5. 데이터 계약 (프론트 ↔ 서버)

> 이 절이 **API 계약의 프론트 측 정본**입니다. 전체 엔드포인트는 [api.md](api.md)를 참조하세요.

### 5-1. 발화 전송 (가장 중요한 API)

**요청**

```http
POST /api/sessions/{sessionId}/messages
Content-Type: application/json

{
  "text": "괜찮아요. 아프면 참지 말고 말하는 게 좋아요.",
  "sttRawText": "괜찮아요 아프면 참지말고 말하는게 좋아요"
}
```

**응답**

```json
{
  "responseMode": "GUIDED",
  "characterMessage": "그렇구나… 그런데 내가 말하면 아버님이 어떤 마음이 되실까?",
  "characterName": "며느리",
  "accumulatedElements": ["EMOTION", "REASON"],
  "turnCount": 3,
  "maxTurns": 6,
  "sceneEnded": false,
  "nextSceneId": null,
  "missionTriggered": null,
  "highlightWords": [
    { "word": "구박", "meaning": "누군가를 못마땅해하며 자꾸 나무라는 것" }
  ]
}
```

**프론트가 하지 말아야 할 것**

- `responseMode`를 프론트에서 판단하지 않기
- `missingElements`를 화면에 그대로 노출하지 않기 (아이에게 "못한 것"으로 읽힘)
- 영문 사고 요소 코드를 아이 화면에 노출하지 않기

### 5-2. 세션 상태 조회 (이어하기용)

```http
GET /api/sessions/{sessionId}
```

```json
{
  "sessionId": "ss01...",
  "storyId": "s01...",
  "status": "in_progress",
  "currentSceneId": "sc02...",
  "currentSceneOrder": 2,
  "totalScenes": 4,
  "turnCount": 2,
  "maxTurns": 6,
  "accumulatedElements": ["PERSPECTIVE"],
  "messages": [ /* 지금까지의 대화 */ ]
}
```

> ⚠️ `totalScenes: 4`는 **화면 기준 장면 수**입니다. DB의 `story_scenes`는 9건(도입1+전개4+대화4)이므로
> `currentSceneOrder`(1~9)와 `totalScenes`(4)의 분모·분자가 맞지 않습니다.
> 진행바를 그리려면 서버가 화면 단위 인덱스를 별도로 내려주는 게 안전합니다. → open-questions Q-10

### 5-3. 상태 코드 참조표

| 위치 | 값 | 프론트 처리 |
| --- | --- | --- |
| `story_sessions.status` | `in_progress` | 이어하기 카드 노출 |
| | `post_activity` | `/activity`로 복귀 |
| | `completed` | 완료 배지 |
| | `stopped` | 이어하기 카드 노출 (중단됨) |
| `responseMode` | `NORMAL` / `GUIDED` / `CLOSING` | §C 공통 매핑표 |
| `scene_end_reason` | `GOAL_MET` / `MAX_TURNS` | 화면 표시 안 함 (내부용) |
| `utterance_validity` | `VALID` / `SHORT` / `UNCLEAR` / `OFF_TOPIC` / `PLAYFUL` | 화면 표시 안 함 |
