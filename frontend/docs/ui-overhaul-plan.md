# UI 개편 실행 계획 — 14개 항목

- **작성일**: 2026-08-13
- **범위**: 프론트엔드 전용. `backend/`·AI 코드는 읽기만 한다
- **기준**: [screens.md](../../docs/spec/screens.md) UI 정본 · [assets.md](../../docs/spec/assets.md) 규격 · [api-spec.md](../../backend/docs/api-spec.md) 서버 계약
- **성격**: 이 문서는 **끝까지 물어보지 않고 진행하기 위한 것**이다. 갈림길마다 결정을 적어 두었다

## Context

기능 연동은 끝났다 — API 20개가 붙고 검증 313건이 통과한다. 남은 것은 **보이는 것**이다.
전달받은 시안 6장과 현재 화면을 대조해 14개 항목이 나왔다.

디자인 시안은 **Stitch에만 있고 Figma로는 받지 못한다.** 화면별 시안도 따로 없다. 그래서
배치·간격·색은 [screens.md §1](../../docs/spec/screens.md)의 디자인 토큰과
[assets.md](../../docs/spec/assets.md)를 근거로 **직접 정한다.** 시안 캡처 6장은 방향 참고로만 쓴다.

## 1. 아바타 (14·완료)

**이미 처리했다.** 원본 6장(1024² · 1.0~1.5MB)의 원 크기·여백이 제각각이라 그리드에서
들쭉날쭉해 보였다. 배경 색을 모서리에서 샘플링해 원을 찾고 같은 비율로 크롭했다.

```
public/characters/1~6.png   원본 (gitignore)
        ↓ sharp — 원 검출 → 정사각 크롭 → 256² WebP
public/avatars/{chick,fox,bear,rabbit,turtle,cat}.webp   각 11~16KB
```

검출된 원 지름 662~708px(편차 7% 이내)로 6장이 같은 무게로 보인다.

**남은 작업**: [`ChildAvatar.tsx`](../src/components/ui/ChildAvatar.tsx)의 색상+이니셜을
이미지로 교체. `AVATAR_IDS`(`color1~6`) → 파일명 매핑 한 곳만 추가하면 A-4·A-5·F-1·H-2가
동시에 바뀐다. **폴백은 남긴다** — 이미지 로드 실패 시 지금의 이니셜 원형으로 돌아간다.

## 3. 대화 화면 개편 — 8 (가장 큼)

`panels.tsx`(425줄)와 `PlayScreen.tsx`의 좌우 패널 조합을 상태별로 다시 짠다.
에셋이 없어도 **폴백으로 구조를 먼저 만든다.**

| 상태 | 좌측 패널 | 우측 패널 |
| --- | --- | --- |
| 장면 도입 C-1·C-2 | 장면 이미지 + 자막 | **캐릭터 영역 삭제** (`WaitingPanel`의 실루엣·마이크 제거) |
| NPC 대사 C-3·C-7 | 장면 이미지 **블러** + 중앙 NPC 얼굴 → 이름 → 대사 | 이 NPC와의 대화 내역 |
| 아이 발화 C-4 | NPC 대사와 동일 | 기존 `ChildTurnPanel`에서 **NPC 프로필 헤더만 제거** |
| 미션 C-10·C-11 | 장면 이미지 | `[미션]` 칩 + 미션명 → 4개 목록 → 키워드 → `말해볼래요` |

### 옮길 때 깨지기 쉬운 것

**대사가 우측 말풍선에서 좌측으로 이동한다.** 따라가야 하는 것:

- `SpeechBubble` · `HighlightedText` — **C-9 단어 팝업 진입 통로**다. 끊기면 단어장까지 막힌다
- `onReplay`("다시 듣기") — 재생 중에만 보이는 버튼이라 위치를 잃기 쉽다
- `turnCount / maxTurns` 표시

우측 대화 내역은 [`ConversationHistory.tsx`](../src/features/play/ConversationHistory.tsx)를
재사용하되 **현재 장면·현재 NPC로 필터**한다 (`message.sceneId === scene.sceneId`).

### 미션

[`MissionCard.tsx`](../src/features/play/MissionCard.tsx)(81줄) 확장. "현재 상태에 해당되는
키워드"는 **서버가 이미 주는 값으로 계산된다** — 새 데이터가 필요 없다.

```
missionTriggered.checklist[].element  (SOLUTION, REQUEST, RESULT …)
accumulatedElements                   (이번 장면에서 모인 것)
        → 아직 안 채운 항목을 골라 그 항목의 label을 키워드로 보여준다
```

미션 2는 미션 1과 같은 구조 + 첫 실패 후 힌트 노출 (D9). 실패 판정은 서버의
`responseMode`·`accumulatedElements` 변화로 본다 — **프론트가 발화 내용을 채점하지 않는다.**

## 4. 별가루 — 11·13

### 화면

- **홈 프로필 칩** — `별가루 24`
- **마이페이지 프로필** — 이름·나이 옆
- **이야기 완료** — `이야기를 끝까지 해냈어!` 아래 `별가루 +5` + 배경 낙하 효과

### 데이터 (D4)

타입에 필드를 **선택**으로 넣고 값이 없으면 칩을 숨긴다.

```ts
MypageSnapshot.stats.starDust?: number      // 누적
HomeSnapshot.child.starDust?: number        // 누적
RetellingResult.earnedStarDust?: number     // 이번에 얻은 양
```

목에는 값을 넣어 화면을 완성하고, 실서버는 필드가 없으니 자동으로 숨는다. 백엔드가 추가하면
코드 변경 없이 나타난다. 요청 문서를 `docs/request/backend/star-dust-exposure.md`로 낸다.

### 낙하 효과

인라인 SVG 별 12~16개 + CSS `@keyframes`(translateY + opacity + 회전). 이미지 파일 없이
`globals.css`에 키프레임 하나 추가. `prefers-reduced-motion`에서는 애니메이션을 끈다.
